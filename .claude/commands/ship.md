出荷レビュー。引数: $ARGUMENTS（`done <出したもの>` / `skip <理由>` / 省略時は週次レビュー）

**目的**: 残った唯一の課題である「出荷経験ゼロ」を潰す。知識ではなく本数を増やす。

正本は `brain/ship-log.md`。まずこれを読む。

## モード

### 省略時（週次レビュー）— これが既定

以下の順に、**この順番を崩さず**進める。

1. **現在地を見せる**（`brain/ship-log.md` の「現在地」ブロックをそのまま提示）
   - 累計出荷数 / 最終出荷日 / **最終出荷からの経過日数**
   - 経過日数は必ず計算して出す（`TZ=Asia/Tokyo date` を使う）

2. **前回決めた1つを聞く**（アカウンタビリティ）
   - ship-log の「次に出す1つ」に書いてある内容をそのまま読み上げて、**出したか聞く**
   - 出していれば称賛して `done` の処理へ
   - 出していなければ責めない。**「合図が弱かった」か「行動が大きすぎた」かだけ切り分ける**

3. **次に出す1つを決める**（1つだけ。複数はNG）
   - 必ず **if-then 形式**で書かせる：「◯◯したら、△△する」
   - 合図は**新しく作らない**。既に必ず起きていることに紐づける
     （例: 毎朝Claudeを開く / 日曜10時にGGG週次が届く / コーヒーを淹れる）
   - 行動は**迷いが出ない粒度**まで割る（「出荷する」✕ →「アップロードする」◯）
   - 大きすぎるなら、**出せる最小単位まで割る**（完成品でなく、1本・1枚・1投稿）

4. **ship-log.md を更新してコミットする**（更新しただけで終わらせない）

### done — 出したものを記録

`brain/ship-log.md` に追記し、現在地ブロックを更新:
- 累計出荷数 +1
- 最終出荷日を今日（JST）に
- 出荷記録に1行追加（日付・何を・どこに）
- 「次に出す1つ」をクリアして、次を決める流れへ

**出したら必ず祝う。** 本数が増えたことを明示する（1本目なら「出荷経験ゼロ」が終わったことを明言）。

### skip — 出せなかった理由を残す

責めずに記録する。ただし**理由は必ず1行残す**（これが次の設計材料になる）。
`brain/ship-log.md` の「出せなかった週の記録」に追記。

同じ理由が3回続いたら、**その理由自体を潰す設計に切り替える**ことを提案する。

## 鉄則

- **1回に決めるのは1つだけ。** 複数決めると全部落ちる
- **「今週こそ」は合図ではない。** いつでもあり、いつでもない
- **完成度で止めない。** 出荷ファースト（`brain/concepts/出荷ファースト.md`）が最上位
- **説教しない。** 出なかった週は設計の問題として扱う。意志の話にしない
- 出荷の定義は広く取る: 公開・納品・投稿・送信・応募 — **他人の目に触れたら出荷**
