# スキル・コマンド 日本語早見表

英語の名前で分かりにくいスキル／コマンドを、日本語で「何をする・いつ使う」でまとめたもの。
`/名前` で呼び出す。迷ったら「この表のどれ？」と聞けばClaudeが選びます。

---

## 🟢 このプロジェクト専用（あなたが作ったもの・全部日本語）

| コマンド | 何をする | いつ使う |
|---|---|---|
| `/check` | lint + build + データ検証をまとめて実行 | 変更した後、壊れてないか確認したいとき |
| `/new-format` | 新しい投稿フォーマットを `formats.yaml` に追加 | フォーマットを増やしたいとき |
| `/order` | 受注案件を処理（ヒアリング→構成案→納品文書） | クライアントの案件が来たとき |
| `/brand-mock` | ブランドの価値観からデザインモックを生成 | ブランドシート／商品モックを作りたいとき |
| `/gokugen` | 5役×3周の高負荷制作（戦略→設計→生成→破壊→仕上げ） | 品質最優先で企画・投稿・営業文を作りたいとき |

## 🔵 品質チェック・レビュー系（英語名だが頻出）

| コマンド | 何をする | いつ使う |
|---|---|---|
| `/code-review` | 変更したコードの差分をレビューし、バグや改善点を指摘 | コードを書いた後、PR前 |
| `/security-review` | 変更にセキュリティ上の問題がないか点検 | 認証・外部通信・機密を触ったとき |
| `/review` | GitHubのプルリクエスト（PR）をレビュー | 他人のPRを見るとき |
| `/simplify` | コードの重複・冗長を整理して簡潔に | 動くけど汚いコードを綺麗にしたいとき |
| `/verify` | 変更が実際に動くかアプリを起動して確認 | 「本当に直った？」を確かめたいとき |

## 🟣 実行・調査系

| コマンド | 何をする | いつ使う |
|---|---|---|
| `/run` | このアプリを起動して動作を見る／スクショ | 画面で確認したいとき |
| `/deep-research` | Web を横断調査し、裏取りした報告書を作る | 事実を集めて調べたいとき（歴史ネタ等） |
| `/init` | コードベースを解析して CLAUDE.md を作る | 新しいリポジトリを整えるとき |
| `/loop` | プロンプトを一定間隔で繰り返し実行 | 定期チェックを回したいとき |

## 🟠 設定・環境系

| コマンド | 何をする | いつ使う |
|---|---|---|
| `/update-config` | settings.json を編集（権限・フック・環境変数） | 「◯◯したら毎回△△して」を自動化したいとき |
| `/fewer-permission-prompts` | よく使う操作を許可リストに追加し確認を減らす | 「許可しますか?」が多くて疲れたとき |
| `/dataviz` | グラフ・チャート・ダッシュボードを綺麗に作る | データを可視化したいとき |
| `/artifact-design` | 共有できるWebページをArtifactとして作る | 見せる資料を作りたいとき |

## ⚙️ 覚えておくと便利な素の操作（スキルではなくコマンド）

| コマンド | 何をする |
|---|---|
| `/effort max` | 推論を最大に深く（重要案件・時間かけて品質優先のとき） |
| `/plan` | いきなり作らず、先に計画を立てて承認をもらう |
| `/context` | いま何にトークンを使っているか可視化 |
| `/rewind` | コードと会話を過去の地点まで巻き戻す |
| `/doctor` | 自分の環境の設定・機能の対応状況を点検 |

---

## 使い方のコツ
- **名前が分からなくてOK**。「差分をレビューして」「動くか確かめて」と日本語で頼めば、Claudeが該当スキルを選んで実行します
- スキルが英語で動き始めても、**説明・結果は日本語で返る**（CLAUDE.md にそう指示済み）
- この表にないスキルが出てきたら「これ何？」と聞けば日本語で説明します
