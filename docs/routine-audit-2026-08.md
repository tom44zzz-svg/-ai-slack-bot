> 🔑 **2026-08-12 追記：なぜClaude側から変更できないのかが判明した**
>
> 8/2〜8/11 は「変更ツールがこのセッションに未接続」と診断していたが、これは誤りだった。
> 8/12 に `update_trigger` を実際に叩いたところ、ツールは存在し、返ってきたのは**権限エラー**:
>
> ```
> this routine was created via "http_api", not by an agent.
> Agents can only update routines they created (via create_trigger).
> A routine's own session may still disable itself (enabled=false only).
> ```
>
> **接続の問題ではなく所有権の問題。** 7件はすべてアプリUI（`http_api` / `meta_mcp`）で作られており、
> エージェントが後から触ることは仕様上できない。**待っていても解決しない。**
> → 下のチェックリストは、いつまで待ってもClaude側では消化されない。**本人のタップ以外に道は無い。**
>
> 唯一の例外：エラー文が名指ししている「自分自身のセッションを持つRoutineは `enabled=false` にできる」。
> 該当するのは毎日レッスン（`trig_01Bzx6bCAmDgebAw4PxfNYZN`、`persistent_session_id` がこのセッション）**だけ**。
> 止めたいのは禁書系なので、これは使わない。

## A. 全件に共通する無駄：使えないMCPが付いている

**7件すべてに MCP コネクタが7〜8個添付されているが、どれも `allowed_tools` に入っていないため1つも呼べない。**

| Routine | 添付MCP数 | allowed_tools |
|---|---|---|
| weekly-ai-report | 8 | Bash / WebSearch / WebFetch |
| ウィークリーAIニュース | 7 | Bash / Read / Write / Edit / Glob / Grep / WebFetch / WebSearch |
| 週次ショート動画 | 8 | WebSearch / WebFetch / Read / Write / Bash |
| GGG週次・月次 | 8 | Bash / Read / Write / Edit / Glob / Grep / WebSearch / WebFetch |
| 禁書PM日報・月報 | 7 | WebSearch / WebFetch / Read / Write / Bash |

添付されているのは Canva / Notion / Slack / Gmail / Google Calendar / Google Drive / vidIQ / freee。
**約160個のツール定義が毎回コンテキストに読み込まれ、一度も使われずに捨てられている。**
（freee は認証切れで接続自体が失敗している）

学習 Day 9「MCPは繋ぎすぎると誤爆＋context rot が同時に起きる」の実例。

### やること
各Routineの編集画面で **コネクタを全部オフにする**。
※ 将来 Notion や Slack に投稿させたくなったら、そのRoutineだけ必要な1個を足す。

## D. YouTube関係5件のレビュー

### D-1. 最大の発見：同じ事業コンテキストが5箇所に手書きコピーされている

禁書PM日報・月報、GGG週次・月次、週次ショート動画 — **5つのRoutineプロンプトに、同じ事業情報が直書きされている**。

- 禁書：チャンネル構成（Ch1/Ch2/Ch3）、ミッション、ベンチマーク → 日報と月報の**両方**に
- GGG：基本情報、店舗体制、勝ちパターン、競合5社、トレンド軸 → 週次と月次の**両方**に

**数字が変わったとき5箇所直さないと、古い前提のまま動き続ける。** 実際にもう古くなっている（下記 D-3）。

→ **これらを `brain/entities/` に移し、Routineプロンプトは「brain/entities/禁書ノオト.md を読んでから」に置き換える。**
1箇所直せば全部に効くようになる。これが Day 20 の「業務OS化」そのもの。

### D-2. 禁書PM日報（毎日）— ✅ **完全ストップと決定（2026-08-02 本人判断）**

プロンプト内の「月内サイクル（1日:企画決定 / 8-14日:素材生成 / 15-21日:編集 / 23日:投稿…）」と「週内サイクル（月:企画 / 火:素材 / 水:ナレ…）」は**完全な固定表**。日付から機械的に決まる。

つまり「今日は何日目だから何をやる」の部分は、**LLMを呼ばなくても分かる**。毎朝LLMを起動して固定表を引き直しているだけ。

LLMが本当に要るのは「そういえばこれも」チップス1つと社長への提案だけ。そのために毎朝 WebSearch 込みのフル実行が走っている。

**→ 決定：Routineごと削除（または無効化）。週1にも落とさず完全に止める。**

日々の進行は `brain/entities/事業-禁書ノオト.md` の「制作サイクル（月内 / 週内）」表を見れば済む。
月30本のLLM実行がゼロになる。

### D-3. 週次ショート動画バズりハック — 参照が古い可能性

2点、確認が要ります。

1. **チャンネル名の不一致**
   このRoutineは「**歴史の裏側** ch」向けと書かれている。一方、禁書PM日報/月報は「**禁書ノオト**（歴史×日本×米沢）」が現行チャンネル。
   同じ人・同じジャンルなのに参照チャンネルが違う。「歴史の裏側」が旧名または停止中のチャンネルなら、**存在しないチャンネル向けに毎週リサーチしている**ことになる。

2. **ベンチマークの数字が3ヶ月以上前**
   プロンプトに「深淵のアーカイブ（2026/04開設、約1ヶ月で2.68万人、1,663万再生）」が固定で書かれている。今は2026-08。
   毎週この古い数字を前提にリサーチしている。→ `brain/` に移して更新する運用にすべき（D-1）。

### D-4. GGG週次・月次 — 重複は大きいが、受注案件なので判断保留

- コンテキストブロック（基本情報・店舗体制・勝ちパターン・競合5社・トレンド軸）がほぼ同一
- 6セクション構成もほぼ同じ。月次は「週次より深い分析・戦略レイヤー」と書いてあるだけ
- 月4回（週次）＋1回（月次）＝月5本

→ **GGGは受注案件なので、納品物として週次が必要なら残すのが正解。** 統合は先方との合意次第。
少なくとも D-1（コンテキストを brain/ に集約）は今すぐやるべき。

### D-5. 禁書PM月報 — ✅ **停止と決定（2026-08-10 本人指示）**

当初は「月1回なので軽微、残す」と判断していたが、**2026-08-10 に本人が禁書ノオト関連の定例を
全停止と指示**。日報とあわせて月報も止める。

理由の整理:
- 日報を止めた時点で、月報だけ残しても**前月の日報が無いので振り返る材料がない**
- マイルストーン表・月内サイクル表は `brain/entities/事業-禁書ノオト.md` にあり、
  必要なときに見れば足りる（＝Day 21 の①「ルールで足りる」）
- 禁書ノオトは ROI戦略上 **②資産ルート（回収6ヶ月）**。`brain/concepts/事業戦略-ROI順.md` は
  「棚上げして、①が回り始めてから再開が正しい」と明記している。定例を止めるのはその方針と一致する
